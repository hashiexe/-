## 1. 前提

| 項目 | 内容 |
|---|---|
| 目的 | **営業用サンプル**。実在の院ではない。制作力を見せて受注につなげる |
| 想定顧客 | 整体院・治療院（本事業のターゲット業種） |
| 商品プラン | サブスク（初期3万＋月1.5万）＝**5ページ構成**に相当する規模で作る |
| 公開先 | Vercel（`hp-biz/` 配下に配置し、既存の営業トップから事例としてリンク） |
| 既存サンプル | `hp-biz/samples/seitai/` に簡易版が1ページある。**今回は本格版を別ディレクトリに作る** |

## 2. 設計思想（最重要）

整体院サイトの目的は見た目の格好よさではなく、**来院前の不安を順番に消すこと**。
患者が抱く不安は、ほぼこの順に現れる。

| 順 | 不安 | サイト上で答える場所 |
|---|---|---|
| 1 | 自分の症状に効くのか | ファーストビュー → 症状別セクション → 症状別ページ |
| 2 | 何をされるのか。痛くないか | 「施術の流れ」「ボキボキしない」の明示 |
| 3 | いくらかかるのか | 料金を上部に。**初回限定価格をファーストビューに置く** |
| 4 | どんな人がやるのか | 院長の顔写真・国家資格・経歴 |
| 5 | 押し売りされないか | **「回数券の強引な販売はしません」と明記** |

**この5つの順番が、そのままトップページのセクション順になる。**

### 判断基準

- 迷ったら「患者の不安が減るか」で決める。装飾より情報
- **スマホ優先。** 整体院サイトの閲覧は8割以上がスマホ
- 料金を隠さない。不明瞭は最大の離脱要因
- 文字を大きめに（40〜60代の利用が多い）。本文 16px 以上

## 3. ページ構成（全5ページ）

| # | ページ | URL | 役割 |
|---|---|---|---|
| 1 | トップ | `/` | 全体の受け皿。不安を5つ順に消し、予約へ流す |
| 2 | 症状別（腰痛） | `/symptoms/lower-back/` | **SEO流入の主力。** 「腰痛 整体 ○○市」で獲る |
| 3 | 料金・施術の流れ | `/price/` | 不安3と2を集中的に解消 |
| 4 | 院・院長紹介 | `/about/` | 不安4を解消。信頼の土台 |
| 5 | アクセス・予約 | `/access/` | 最後の一押し。道順まで具体的に |

### 商品設計上の補足

症状別ページは本来 5〜6本必要（腰痛・肩こり・頭痛・産後骨盤・坐骨神経痛・スポーツ障害）。
**これを「月額プランで毎月1本ずつ追加していく」という売り方にすると、月1.5万円の根拠が明確になる。**
サンプルでは腰痛1本のみ作り、他はトップからのリンクに「準備中」を置かず、
腰痛ページ下部に「他の症状ページも順次公開」と記載する形で自然に見せる。

## 4. 各ページのセクション構成

### 4.1 トップページ `/`

| 順 | セクション | 内容 |
|---|---|---|
| 1 | ヘッダー（sticky） | 院名ロゴ／ナビ／**電話ボタン（常時表示）** |
| 2 | ファーストビュー | 初回限定価格バッジ／H1（症状＋ベネフィット）／選ばれる理由4点のチェックリスト／CVボタン2つ／施術写真 |
| 3 | こんなお悩みはありませんか | 症状カード6枚。**各カードから症状別ページへリンク** |
| 4 | 当院が選ばれる理由 | 3〜4項目。アイコン＋見出し＋本文 |
| 5 | 施術の流れ | 初回60分を5ステップで。各ステップに所要時間を明記 |
| 6 | 料金 | 初回価格を大きく。詳細は料金ページへ |
| 7 | 患者さまの声 | 3件。年代・性別・職業を添える |
| 8 | 院長紹介 | 顔写真／保有資格／経歴／一言メッセージ |
| 9 | よくある質問 | 5〜6問。アコーディオン |
| 10 | アクセス | Googleマップ埋め込み／営業時間表 |
| 11 | 予約フォーム | 項目は5つまで |
| 12 | フッター | 院名／住所／電話／サンプルである旨の注記 |
| — | スマホ固定CVバー | 画面下部に「電話する／予約する」を常時表示 |

### 4.2 症状別ページ `/symptoms/lower-back/`

**このページがSEOの本体。** 他ページより文章量を厚くする（2,000〜3,000字相当）。

| 順 | セクション | 内容 |
|---|---|---|
| 1 | H1 | 「○○市で腰痛にお悩みの方へ」形式。**地域名を必ず入れる** |
| 2 | 症状チェックリスト | 「こんな症状でお困りではありませんか」8項目程度 |
| 3 | なぜ腰痛が起こるのか | 原因の解説。**ここで専門性を示す。** 図解があるとなお良い |
| 4 | よくある誤解 | 「マッサージしても戻るのはなぜか」など。差別化になる |
| 5 | 当院のアプローチ | 検査 → 施術 → セルフケアの流れ |
| 6 | 施術を受けた方の例 | **§6の広告規制に必ず従う。** 効果保証の表現は使わない |
| 7 | 料金 | 初回価格を再掲 |
| 8 | よくある質問 | 腰痛に特化した5問 |
| 9 | 予約CTA | |
| 10 | 他の症状へのリンク | 内部リンク。回遊とSEOの両方に効く |

### 4.3 料金・施術の流れ `/price/`

1. 料金表（初回／2回目以降／産後骨盤ケア／学生割引など）
2. **「表示料金以外に追加費用はかかりません」の明記**
3. **「回数券の強引な販売はいたしません」の明記** ← 不安5への回答
4. 支払い方法（現金・カード・QR）
5. 初回の流れ（60分の内訳を時間配分つきで）
6. 持ち物・服装の案内
7. 予約CTA

### 4.4 院・院長紹介 `/about/`

1. 院長プロフィール（顔写真・保有資格・経歴・この仕事を選んだ理由）
2. 当院の考え方（施術方針）
3. 院内紹介（写真3〜4枚）
4. 設備・衛生管理
5. 予約CTA

### 4.5 アクセス・予約 `/access/`

1. Googleマップ埋め込み
2. 住所・電話・営業時間・休診日
3. **駅からの道順（写真つきで手順化）** ← 離脱防止に効く
4. 駐車場案内
5. 予約フォーム
6. LINE予約ボタン

## 5. CV（予約）導線の設計

| ルール | 内容 |
|---|---|
| 電話 | `tel:` リンクでタップ発信。**ヘッダーとスマホ固定バーに常時配置** |
| フォーム項目 | **5つまで**（名前／電話／希望日／症状／備考）。多いほど離脱する |
| 固定バー | スマホのみ画面下部に固定。「電話する」「予約する」の2ボタン |
| 配置頻度 | 1〜2セクションごとにCVボタンを置く |
| 初回価格 | ファーストビューの最上部。**これが最大のフック** |

## 6. 広告規制チェックリスト（差別化ポイント）

治療院には柔道整復師法・あはき法に基づく広告規制がある。
**規制を理解している制作者は少ないため、対応できること自体が営業の武器になる。**

> ⚠️ 適用範囲は院の資格形態（柔道整復師／鍼灸師／無資格の整体）によって変わる。
> **実案件では必ず院の資格形態を確認すること。** 本サンプルでは安全側に倒して制作する。

### 使わない表現

| NG | 理由 |
|---|---|
| 「治る」「完治」「治療」 | 効能効果の標榜。**「施術」「ケア」に置き換える** |
| 「○○病が改善します」 | 効果の保証・断定 |
| 「日本一」「地域No.1」「最高の」 | 客観的根拠のない最上級表現 |
| 極端なビフォーアフター写真 | 誤認を招く |
| 「必ず」「絶対に」 | 効果の保証 |

### 使ってよい表現

- 「施術」「ケア」「アプローチ」「お悩みに対応しています」
- 保有する国家資格の明示（柔道整復師・鍼灸師など）
- 料金、営業時間、住所、電話番号、施術メニュー
- 患者の声（**効果を保証しない表現に留める**。「楽になりました」等の主観表現に限る）

### 実装時のチェック

- [ ] 「治療」「治る」「完治」で全文検索し、0件であること
- [ ] 最上級表現（日本一・No.1・最高）が無いこと
- [ ] 患者の声に効果保証の断定がないこと
- [ ] 資格の記載が実態と矛盾しないこと（サンプルでは「柔道整復師」設定とする）

## 7. SEO設計

| 項目 | 内容 |
|---|---|
| 主戦場 | **ローカル検索。**「整体 ○○市」「腰痛 ○○駅」 |
| 流入の主力 | 症状別ページ |
| title | `腰痛の施術｜○○整体院｜○○市○○駅 徒歩5分` の形式。**地域名を必ず入れる** |
| description | 120字前後。症状・地域・初回価格・資格を含める |
| 見出し | H1は各ページ1つ。H2以降で構造化 |
| 構造化データ | **JSON-LD で LocalBusiness スキーマ**を全ページに入れる（住所・電話・営業時間・地図座標） |
| NAP統一 | 院名・住所・電話の表記を**Googleビジネスプロフィールと完全一致**させる。MEO運用とセットで売れる |
| 内部リンク | トップ ⇄ 症状別 ⇄ 料金 を相互リンク |
| 画像 | 全画像に alt。WebP。遅延読み込み |

## 8. デザイン・技術仕様

### デザイン方針

| 項目 | 指定 |
|---|---|
| トーン | 清潔・信頼感。**医療寄りだが冷たくしない** |
| メインカラー | 深めの青緑（信頼感・清潔感）。例 `#1c7a84` |
| アクセント | 暖色オレンジ（CVボタン専用）。例 `#f5a623` |
| 背景 | 白＋淡いグレーブルーの交互 |
| フォント | Noto Sans JP。**本文16px以上**（40〜60代が主対象） |
| 角丸 | 中程度（7〜10px）。柔らかい印象に |
| 写真 | サンプルではCSSグラデーションのプレースホルダで代用し、「施術写真」等のラベルを入れる |

### 技術仕様

| 項目 | 採用 |
|---|---|
| フレームワーク | **Astro**（複数ページ・症状別ページの量産に適する） |
| 代替 | Astroのセットアップが重い場合は**静的HTML＋共通CSSファイル**でも可。判断はSonnetに委ねる |
| ホスティング | Vercel（静的出力） |
| フォーム | サンプルではJSでダミー送信。実案件では Formspree |
| 地図 | Googleマップの `output=embed` |
| 解析 | サンプルには入れない |
| 依存 | **外部ライブラリは使わない。** フォントのみ Google Fonts |
| 対応 | レスポンシブ必須。360px幅で横スクロールが出ないこと |

## 9. Sonnetへの実装指示（そのまま貼る）

```
hp-biz/specs/seitai-site-spec.md を読んで、整体院のサンプルサイトを制作してください。

- 出力先は hp-biz/samples/seitai-full/ 配下
- 仕様書の §3〜§8 に従って全5ページを制作
- §6 の広告規制チェックリストは必ず守り、最後に全文検索で確認すること
- §8の「架空の院の設定」を全ページで統一
- 外部ライブラリは使わず、共通CSSは assets/style.css に集約
- 360px幅で横スクロールが出ないこと
- 全ページのフッターにサンプルである旨を明記
- 完成後、各ページのHTMLタグの対応が取れているか検証してからコミット

文章は実際に公開できる品質で書いてください。ダミーテキストは使わないこと。
```
