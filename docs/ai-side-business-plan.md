### 1.1 「禁止事項B」の正確な意味

本人の意図は**「オンラインに実名を晒したくない」**であり、商談相手・契約書・請求書に実名が出ることは許容。

| 売り方 | 実名のオンライン公開 | 可否 |
|---|---|---|
| スキルマーケット（ココナラ等） | 不要（ニックネーム表示。本人確認は運営に対してのみ） | **○** |
| 1対1の商談 → 業務委託契約 | **不要**（通信販売ではないため特商法の対象外） | **○** |
| アフィリエイト / 広告収益 | 不要（自分が販売者ではないため） | **○** |
| Kindle / note / BOOTH | 不要（ペンネーム可） | **○** |
| 自サイト＋Stripe直販（BtoC通信販売） | 氏名の表示が原則 | **△** |

### 1.2 「禁止事項A」の再定義（第3版）

## 2. 第1版からの方針転換

### 2.1 FP軸を撤回した理由

1. **本人の意欲が続かない。** 飽きたものを半年続ける計画は、計画として成立しない。
2. **SEO上も不利だった。** 金融はGoogleがYMYL（人の財産に関わる領域）として最も厳しく評価する分野で、
   **個人・匿名・実務経験なし**という条件はSEOで最悪の組み合わせ。
   本人が既に `moneybase-fp.com` で集客に失敗しているのは、**能力ではなくジャンル選定の問題**である可能性が高い。
3. 第1版のA案（FPツール×アフィリエイト）は、この壁を「記事ではなくツールを作る」で回避する設計だったが、
   意欲の問題は回避できない。

→ **軸を「FP資格」から「エンタープライズ法人営業5年」に移す。**
   こちらの方が希少性が高く、実務経験があり、市場に明確な困りごとが存在する。

### 2.2 既存サイト `moneybase-fp.com` の扱い

- ドメイン名がFP縛りのため、他ジャンルへの転用は困難。**寝かせる。**
- ただし**「なぜ集客できなかったか」の分析には価値がある**（次に同じ失敗をしないため）。
- 現時点では Claude の実行環境からegressブロックにより閲覧できず、診断は未実施。
  → Claude on Chrome で本人環境から確認するか、内容を共有してもらう。

## 5. 確定案：ホームページ制作＋月額運用

### 5.1 価格（サブスク型で確定）

| プラン | 初期 | 月額 | 内容 |
|---|---|---|---|
| ライト | 8万円 | 5,000円 | 1ページ。月1回まで更新 |
| **サブスク（主力）** | **3万円** | **15,000円**（12ヶ月〜） | 5ページ。**更新無制限**＋MEO＋月次レポート |
| 買い切り | 15万円 | 10,000円（任意） | 5ページ。保守は任意 |

**月3社で目標達成（月4.5万）。** 初期費用の壁を壊すことで受注しやすく、かつストック収入になる。
ドメイン代（年1,500円前後）は顧客の実費負担。

### 5.2 ターゲット業種：整体院・治療院に絞る

**絞る理由**

- **制作が速くなる** … 構成・文章・写真指示をテンプレ化でき、2件目以降の工数が激減する
- **営業が刺さる** … 「整体院専門」は「何でも作ります」より圧倒的に響く
- **紹介が回る** … 同業者に横のつながりがある
- **リスト作成が機械化できる** … Googleマップから業種で機械的に抽出できる

**業種の比較**

| 業種 | Web集客の重要度 | 支配的プラットフォーム | 紹介 | 判定 |
|---|---|---|---|---|
| **整体院・治療院** | **高**（新規患者が命綱） | **なし** | 高 | **◎本命** |
| 工務店・リフォーム | 高（1件の単価が大きい） | なし | 中 | ○対抗 |
| 美容室 | 中 | **ホットペッパー** | 高 | △ |
| 飲食店 | 低〜中 | **食べログ** | 中 | ✕ |

**決め手は「支配的プラットフォームが存在しない」こと。**
美容室はホットペッパーに月5〜10万を支払っており、HPに追加予算を出す余力がない。
飲食店は食べログで足りてしまううえ、単価が最も低く廃業率も高い（＝月額が止まりやすい）。
**整体院にはその逃げ道がないため、自前のHPの価値が相対的に高い。**

**⚠️ 広告規制（差別化の機会でもある）**

治療院には柔道整復師法・あはき法に基づく広告規制があり、「治る」「改善する」等の表現に制限がある。
違反は顧客側のリスクになるため、原稿作成時に必ず確認する。
**規制を理解している制作者は少ないため、「広告規制に配慮した原稿を作ります」は強い差別化になる。**

※ サンプル3本（居酒屋・美容室・整体院）はそのまま残す。「他業種も対応可」の証明として機能する。
　 営業の主軸のみ整体院に寄せる。

### 5.3 集客（知人ルートが無いため2本立て）

> **確定事実: 本人に「HPがない／古い」事業者の心当たりは無い。**
> よって第4版で保険扱いにしたクラウドソーシングを、**現実的な第1ルートに戻す。**

| ルート | 内容 | 期待値 | 本人の負担 |
|---|---|---|---|
| **A クラウドソーシング** | ランサーズ／クラウドワークス／ココナラ。**需要が既にある** | 確実だが単価が安い（3〜15万） | 提案文を送る（Claude が作成） |
| **B Googleマップ営業** | 「HPなし／古いHP」の店舗リストを Claude が作成し、問い合わせフォームから提案 | **返信率1〜3%**。100件で1〜3件 | 送信と商談。**営業力が効くのはこちら** |

**Aで実績を作りながら、Bで単価の高い直接契約を狙う。** 実績が2〜3件たまった時点でBの返信率が上がる。

### 5.4 技術構成（WordPressは使わない）

| 用途 | 採用 | 費用 |
|---|---|---|
| 制作 | 静的HTML（小規模）／**Astro**（複数ページ・CMS連携時） | 無料 |
| 公開 | **Vercel** または Cloudflare Pages | **無料** |
| ドメイン | 顧客名義で取得 | 年1,500円前後（顧客実費） |
| CMS（必要時） | Googleスプレッドシート連携 / microCMS | 無料枠 |
| フォーム | Formspree / Google Forms | 無料枠 |
| 解析 | GA4 + Search Console | 無料 |

**これがそのまま営業トークになる**（いずれも事実）:
1. **サーバー代0円**（WordPressは月1,000円前後 ＝ 年1.2万円の削減）
2. **表示が速い**（Googleの評価にも効く）
3. **乗っ取り・プラグイン更新の心配がない**

### 5.5 修正対応のフロー

顧客の依頼 → **本人が Claude に一言伝える** → Claude が修正・デプロイ。**1件5分以内。**
月3〜5社でも30分/日に収まる。本人の作業は実質「転記」のみ。

### 5.6 顧客の自己編集

| 方式 | 採用方針 |
|---|---|
| **依頼のみ（既定）** | **月額保守を売る根拠になるため、これを既定とする** |
| Googleスプレッドシート連携 | 「自分で更新したい」と言われた場合。営業時間・メニュー・お知らせ向け |
| microCMS | 本格的な更新需要がある場合のみ |

**方針: お知らせ・メニューのみ顧客が編集、デザイン変更は依頼。**
全部を顧客が編集できると、月額保守が売れなくなる。

### 5.7 買い取り・譲渡の設計

**設計の要: ドメインは最初から顧客名義で取得する。**
譲渡が簡単になるうえ、「囲い込まれていない」という安心感が営業でも効く。

**引き渡すもの**

| 対象 | 方法 | 所要 |
|---|---|---|
| ドメイン | **最初から顧客名義** → 管理ID/PWを渡すだけ | 5分 |
| ソースコード | GitHubリポジトリを譲渡（無料）または ZIP納品 | 10分 |
| ホスティング | Vercelプロジェクトを顧客アカウントへ移管 | 15分 |
| GA4／Search Console | 管理者権限を付与し、こちらを外す | 10分 |
| 手順書 | Claude が作成 | — |

**顧客が編集できる状態で渡す**

| 方式 | 顧客の難易度 | 費用 | 判定 |
|---|---|---|---|
| **microCMS** | 低（管理画面で文章・画像を編集。UIが日本語） | 無料枠で足りる | **◎買い取り時の標準** |
| Googleスプレッドシート連携 | 最低（Excel感覚） | 無料 | ○ 項目が固定の部分向け |
| Decap CMS | 中（設定が必要・UIが英語寄り） | 無料 | △ |
| コードをそのまま渡す | 高 | — | ✕ 実質編集不能 |

**買取価格**

| 項目 | 金額 |
|---|---|
| 買取価格 | **20〜30万円**（サブスク開始12ヶ月後から） |
| 譲渡手数料 | 3〜5万円（環境移管＋手順書＋1時間のレクチャー） |

月額1.5万円の**1.5〜2年分**に設定する。
**「いつでも買い取れます」と言えること自体が営業の武器になる**（囲い込みへの不安を消せる）一方、
実際に買い取られても損をしない価格帯。

## 10. 制作コストと Claude の運用ルール

### 10.1 実測値（サンプル4ページの制作実績より）

| ページ | 文字数 | 出力トークン |
|---|---|---|
| 居酒屋サンプル | 11,333字 | 約3,500 |
| 美容室サンプル | 11,426字 | 約3,500 |
| 整体院サンプル | 15,043字 | 約4,600 |
| 営業用トップ | 16,993字 | 約5,200 |

**1サイト＝出力3,500〜5,000トークン。**
ただしコストの大半は出力ではなく、**修正のたびに会話履歴全体を再送する入力側**が占める。

### 10.2 API換算のコスト（Opus 5：入力$5／出力$25 per 1M）

| ケース | コスト |
|---|---|
| 軽め（修正少・8往復） | 約135円 |
| 標準（修正5回・12往復） | 約270円 |
| 重め（修正20往復） | 約600円 |
| 保守1社（月2〜4回の更新） | 約30円／月 |
| **顧客3社の運用＋新規1本** | **約360円／月** |

実案件はヒアリングや画像が入るため上振れするが、3〜5倍見ても月1,000〜2,000円。
**予算1〜3万円に対して1桁余っており、トークンコストは制約にならない。**

### 10.3 実質のボトルネック

| 制約 | 上限 |
|---|---|
| トークン・費用 | 月37〜111本 |
| Claude の制作速度 | 週5本以上でも可 |
| **本人のレビュー（1本30〜60分）** | **週2〜3本** |
| **受注できる件数** | **月0〜1本**（実質の上限） |

**「作れるか」ではなく「売れるか」が全て。** コストを理由に制作を絞る必要はなく、
むしろサンプルを増やして営業材料にする方が費用対効果が高い。

### 10.4 Claude Code Pro での運用ルール

利用形態は **Claude Code Pro（サブスク）**。上限は **5時間のローリングウィンドウ＋週次ウィンドウ**の二段構えで、
Claude チャットとも共有される。Pro の具体的な数値上限は公式ドキュメントに記載がないため、
`/usage` での実測を前提とする。

| ルール | 理由 |
|---|---|
| **サイト制作は Sonnet で行う** | 定型的な実装作業では品質が落ちず、消費が大幅に減る（公式ドキュメントの推奨） |
| **事業方針の相談のみ Opus** | 複雑な判断・多段推論にのみ使う |
| **1サイトごとに `/clear`** | 使用量急増の最大要因は長時間セッション。履歴は毎リクエスト再送される |
| **`/usage` で実測する** | 1サイト作った直後に確認すれば、週何本可能かが判明する |
| 上限に当たったら | `/model` で Sonnet に切替（モデル別上限の場合）、または `/usage-credits` を追加 |

**見込み**: Sonnet ＋ サイトごとの `/clear` なら **週1〜2本が現実的**。
本事業に必要なのは **週1本**（3ヶ月で3社）のため、**Pro で足りる。**
足りなくなる状況は受注が増えている状況なので、その時点で Max か usage credits を検討すればよい。
